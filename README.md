# 加拿大冰酒 ERP

给冰酒生意做的一套轻量进销存 + 市集利润管理系统。用 Go 写成一个静态二进制，
Docker 一条命令部署，数据放在一个 SQLite 文件里，**没有外部依赖、没有云服务、数据完全在你自己的服务器上**。

---

## 它解决什么问题

你在市集上摆摊卖冰酒，最想知道的是：**这一场市集到底赚了多少？试饮花了多少成本？**

这套系统的做法是：

1. 录**产品档案**（SKU、年份、容量、售价）。
2. 录**采购入库**，把运费、关税摊进每一瓶的到岸成本。
3. 每场市集建一张**市集活动**，填每个产品的**带去 / 试饮 / 销售 / 赠送 / 损耗**数量与售价，再加上摊位费、交通费。
4. 点「结算」，系统自动扣减库存、锁定成本，并算出这一场的**销售额、毛利、净利润、净利率、试饮带动倍数**。
5. 首页看板与报表随时看整体经营情况，一键导出 Excel。

### 功能一览

| 模块 | 说明 |
| --- | --- |
| 经营看板 | 库存总值、本月销售与净利润、近 12 个月趋势、各市集利润对比、畅销产品、低库存预警 |
| 产品档案 | SKU / 名称 / 英文名 / 品类 / 年份 / 容量 / 每箱瓶数 / 售价 / 库存预警线 / 供应商；含单品的市集表现与库存流水 |
| 供应商 / 客户 | 联系方式、地址、国家（供应商专用）、启用停用 |
| 采购入库 | 多行明细、运费/关税/其他费用按金额或数量比例分摊、自动算到岸单价、确认入库才动库存、可撤销入库 |
| 库存管理 | 实时库存与库存成本、移动加权平均成本、低库存预警、库存流水台账（每笔都留结存快照） |
| 出入库登记 | 期初建账、盘点调增/调减、退货入库、破损损耗、赠送用酒 |

| 系统 | 多用户 + 4 种角色权限、操作日志、数据库备份、库存重算 |
| 手机 App | PWA：可「添加到主屏幕」，全屏运行、独立图标，网络不稳时自动重试保存 |

## 30 秒快速开始（Docker）

前提：服务器上装好 Docker 与 Docker Compose。

```bash
# 1. 把整个目录传到服务器，例如 /opt/icewine-erp
cd /opt/icewine-erp

# 2. 可选：生成本地配置（不改也能跑）
cp .env.example .env

# 3. 构建并启动
docker compose up -d --build

# 4. 看日志确认起来了
docker compose logs -f erp
```

打开 `http://服务器IP:8000`，用默认账号登录：

- 用户名：`admin`
- 密码：`admin123`

> **第一次登录后请立刻到「我的账号 → 修改密码」改掉默认密码。**

想先看看系统长什么样，可以在 `.env` 里设置 `ERP_SEED_DEMO=1` 再启动一次，
系统会写入 4 款冰酒、1 张采购入库单、3 场已结算市集和 1 场筹备中的市集作为演示数据
（只在数据库里还没有产品时写入，正式使用保持 `0`）。

## 核心计算口径（重要）

这一节解释系统里的每个数字是怎么来的。数字能不能信，取决于口径是否清晰。

### 1. 移动加权平均成本

库存不是按「批次」算的，而是每次入库后重算一个平均成本：

```
入库后平均成本 = (原库存数量 × 原平均成本 + 入库数量 × 到岸单价) ÷ (原库存数量 + 入库数量)
出库时成本     = 当前平均成本（出库不改变平均成本）
```

好处是账目简单、不需要维护批次；缺点是同一款酒不同批次的价格差异会被平均掉。
对「一次进一批货、慢慢卖」的生意，这是最省心的方式。

库存价值始终等于 `库存数量 × 平均成本`，系统不会累积浮点误差。

### 2. 到岸成本分摊（采购入库）

运费、关税这些钱不是「费用」，而是要摊进每一瓶的成本，否则利润会算高：

```
某行到岸单价 = (该行货款 + 该行分摊到的附加费用) ÷ 该行数量
```

分摊方式有两种，在采购单上选择：

- **按货款金额比例**（默认，会计上最常用）：买得贵的品种多摊一点。
- **按入库数量比例**：更适合按瓶计费的运费。

前 n-1 行按比例取整，最后一行取剩余金额，保证分摊合计**恰好等于**费用总额，不会出现分位差额。

### 3. 市集利润

```
销售额      = Σ(销售数量 × 单价 − 该行优惠)
售出成本    = Σ(销售数量 × 单位成本)
试饮成本    = Σ(试饮数量 × 单位成本)
赠送损耗    = Σ((赠送数量 + 损耗数量) × 单位成本)
活动费用    = Σ 费用明细（摊位费 / 交通 / 餐饮 / 包装 / 人工 / 其他）

毛利        = 销售额 − 售出成本
净利润      = 销售额 − 售出成本 − 试饮成本 − 赠送损耗 − 活动费用
净利率      = 净利润 ÷ 销售额
试饮带动倍数 = 销售瓶数 ÷ 试饮瓶数
```

**试饮按「瓶」记录**（不是按杯）：市集上你开几瓶用于试饮就填几瓶，
系统按整瓶成本计入试饮成本，同时把这部分库存扣掉。
如果你习惯按杯数，可以按「每瓶倒多少杯」自己换算后填入。

### 4. 结算与成本快照

- **未结算**的市集，成本按产品的**当前平均成本**计算，页面上标注「预估值」。
  这时候再去采购一批便宜的酒，这场市集的利润数字会跟着变。
- **结算**时系统做三件事：① 把当时的平均成本**快照**写入每条明细；
  ② 按试饮 + 销售 + 赠送 + 损耗扣减库存；③ 固化损益到报表。
  之后采购价怎么变，这场市集的历史利润都不再变动。
- **撤销结算**会删除这场市集产生的库存流水，并按剩余流水重算受影响产品的平均成本
  （因为流水被移除了，之后所有依赖它的加权平均需要重新推演）。撤销后即可继续修改数量。

### 5. 账本是「过账顺序」，补录单据不会改写历史

每一次库存变动都会立刻写一条流水，并记下当时的结存数量、结存均价、结存金额。
流水是**只增不改**的，重算库存时按**过账顺序**（不是业务日期）重新推演。

这意味着：如果你今天补录一张上个月的采购单，系统不会回头改写那一个月已经算过的成本，
而是从补录那一刻起影响之后的加权平均。这也是所有正规 ERP 的行为——
**已结算的历史成本不会因为后补单据而变化**，否则每次补单，历史利润都会变，
报表就没法对账了。补录时请留意业务日期只用于报表归集，不用于成本计算。

### 6. 库存不足会被拦住

结算时如果某个产品的库存不够扣（例如试饮 + 销售超过账面库存），
系统会**拒绝结算**并列出缺口，不会偷偷把库存做成负数。
解决办法：补录采购入库，或到「出入库登记」做期初建账/盘点调整。

盘点后如果确实与账面不符，用「出入库登记 → 盘点调增/调减」把账做平。

## 日常使用流程

```
第一次使用
  1. 系统设置 → 改公司名、币种符号、默认库存预警线
  2. 用户管理 → 给店员/合伙人开账号、分配角色
  3. 产品档案 → 建好每款冰酒（SKU、年份、容量、售价、预警线）
  4. 供应商 → 录入酒庄/进口商
  5. 出入库登记 → 「期初建账」把手上已有的库存录进去
     （或直接走第 6 步的采购入库）

每一批货到
  6. 采购入库 → 新建 → 选供应商、加明细行、填运费/关税 → 保存
  7. 核对无误 → 点「确认入库」 → 库存与平均成本更新

每一场市集
  8. 市集活动 → 新建 → 填名称、日期、场地
  9. 在详情页逐个「添加产品」，填带去数量
 10. 市集当天在手机上随时填试饮 / 销售 / 赠送 / 损耗，改动会自动保存
 11. 加上摊位费、交通费等费用
 12. 收摊后核对 → 点「结算本场市集」 → 库存扣减、利润锁定

日常查看
 13. 首页看板看整体；报表页看单场明细与产品销售排行
 14. 需要给合伙人 / 报税就导出 Excel
```

## 手机安装成 App（PWA）

系统内置了 PWA 支持：装到手机桌面后可以像 App 一样全屏打开，
市集现场点一下图标就进去了，不用每次输网址。

> **重要：PWA 安装与离线缓存需要 HTTPS。**
> 用 `http://192.168.x.x:8000` 这种局域网地址访问时，浏览器不允许注册
> Service Worker，「添加到主屏幕」只能生成一个普通书签（功能完全可用，
> 但没有全屏运行和离线兜底）。想完整体验请按下面配 HTTPS。

### 方式 A：有域名（推荐，全自动）

把域名解析到服务器，然后在 `.env` 里：

```env
ERP_DOMAIN=erp.你的域名.com
ERP_CADDYFILE=Caddyfile.domain
ERP_COOKIE_SECURE=1
```

```bash
docker compose --profile https up -d
```

Caddy 会自动申请并续期 Let's Encrypt 证书。用手机打开 `https://erp.你的域名.com`。

### 方式 B：只有局域网 IP（自签证书）

```env
ERP_DOMAIN=192.168.1.10     # 换成你服务器的局域网 IP
ERP_CADDYFILE=Caddyfile.internal
ERP_COOKIE_SECURE=1
```

```bash
docker compose --profile https up -d

# 导出 Caddy 的根证书
docker compose exec caddy cat /data/caddy/pki/authorities/local/root.crt > root.crt
```

把 `root.crt` 传到手机并安装、信任：

- **iPhone**：把 `root.crt` 用 AirDrop 或邮件发到手机 → 设置 → 通用 → VPN与设备管理 → 安装描述文件
  → 再进「设置 → 通用 → 关于本机 → 证书信任设置」打开完全信任。
- **Android**：设置 → 安全 → 加密与凭据 → 安装证书 → CA 证书。

之后用手机打开 `https://192.168.1.10`（注意是 https）。

### 安装步骤

- **iPhone / Safari**：打开站点 → 点底部「分享」→「添加到主屏幕」。
- **Android / Chrome**：打开站点 → 右上角菜单 →「安装应用」或「添加到主屏幕」。
  页面顶部也会自动出现一条「立即安装」提示条。

### 断网了怎么办

- 页面顶部会出现橙色提示，明确告诉你当前网络不可用。
- 在市集录入页改数字时，如果提交失败，该行会变成橙色并**自动重试**（1、2、4、8、15 秒递增，最多 5 次）。
- 改完数字先别切走，等该行恢复成绿色/无色说明已保存成功再继续。
- 离线提示页会告诉你「等信号恢复后重新提交即可」，不会有数据被悄悄丢掉。

## 角色与权限

系统内置四种角色。**店员与只读角色看不到任何成本与利润数据**——这条不是靠把数字藏起来，
而是后端就不把数据传给页面，并且有自动化测试逐个页面审计。

| 能做什么 | 管理员 | 经理 | 店员 | 只读 |
| --- | :-: | :-: | :-: | :-: |
| 查看经营看板 | ✅ | ✅ | ✅（不含成本利润） | ✅（不含成本利润） |
| 产品 / 供应商 / 客户档案 | ✅ | ✅ | 只能看，供应商客户可改 | 只能看 |
| 采购入库录入（草稿） | ✅ | ✅ | ✅ | — |
| 确认入库 / 撤销入库 | ✅ | ✅ | — | — |
| 市集活动创建与试饮销售录入 | ✅ | ✅ | ✅ | — |
| 市集结算 / 撤销结算 | ✅ | ✅ | — | — |
| 查看库存数量与库存流水 | ✅ | ✅ | ✅（不含成本列） | ✅（不含成本列） |
| 出入库登记（期初、盘点、损耗） | ✅ | ✅ | — | — |
| 成本与利润报表、导出 | ✅ | ✅ | — | — |
| 用户管理 / 操作日志 | ✅ | — | — | — |
| 系统设置 / 数据维护 | ✅ | ✅ | — | — |

**店员能看到什么、看不到什么**（这是设计上刻意划分的边界）：

- 能看到：产品档案、售价、采购单价与采购金额（货是他们收的，单价来自发票）、
  库存**数量**、市集的试饮/销售/赠送/损耗数量、销售额、自己录入的全部单据。
- 看不到：**移动加权平均成本、库存成本与库存总值、单位成本、结存均价、毛利、净利润、净利率、试饮成本**。

也就是说，店员可以独立完成「收货录入 + 摆摊记数」这两件事，
但看不到任何由系统派生出来的成本与利润口径。结算与盘点这类会锁定账目的动作留给管理员/经理。

权限模型是固定的四种角色（够用、不容易配错）。如果你需要「能结算但不能看成本」这类组合，
告诉我，可以改成细粒度权限点。

## 数据、备份与恢复

所有数据都在 `./data/` 目录：

```
data/
├── erp.sqlite3          主数据库（WAL 模式）
├── erp.sqlite3-wal      预写日志（正常运行时存在）
├── secret.key           自动生成的会话签名密钥（删掉会导致所有人需要重新登录）
├── backups/             备份目录
│   └── erp-backup-20251002-153000.sqlite3
└── caddy/               HTTPS 证书（启用 Caddy 时）
```

### 备份

三种方式，任选：

```bash
# 方式 1：网页上点「系统设置 → 立即备份数据库」
# 方式 2：命令行
docker compose exec erp /app/erp backup /data/backups
# 方式 3：定时脚本（推荐，保留最近 30 份）
./scripts/backup.sh
# crontab 每天凌晨 3 点
0 3 * * * cd /opt/icewine-erp && ./scripts/backup.sh >> /var/log/erp-backup.log 2>&1
```

备份用的是 SQLite 的 `VACUUM INTO`，**可以在系统运行中安全执行**，不会锁库、不会拷到一半的半成品。

### 恢复

```bash
docker compose down
cp data/backups/erp-backup-20251002-153000.sqlite3 data/erp.sqlite3
rm -f data/erp.sqlite3-wal data/erp.sqlite3-shm
docker compose up -d
```

### 忘记密码

```bash
docker compose exec erp /app/erp reset-password admin
# 输入新密码即可
```

## 反向代理与 HTTPS

除了内置的 Caddy 方案，你也可以放在已有的 Nginx 后面：

```nginx
server {
    listen 443 ssl http2;
    server_name erp.example.com;

    ssl_certificate     /etc/letsencrypt/live/erp.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/erp.example.com/privkey.pem;

    client_max_body_size 16m;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;
    }

    # Service Worker 不能长缓存，否则更新不生效
    location = /static/sw.js {
        proxy_pass http://127.0.0.1:8000;
        add_header Cache-Control "no-cache, no-store, must-revalidate";
    }
}
```

走 HTTPS 后记得把 `.env` 里的 `ERP_COOKIE_SECURE=1` 打开（Cookie 只在加密连接上传输）。

如果不想暴露端口到公网，可以把 `ERP_BIND` 改成 `127.0.0.1`，
再用 Tailscale / Cloudflare Tunnel / frp 之类的方式让手机连进来。

## 私有仓库与自动构建（GitHub Actions）

代码放在私有仓库里，镜像由 GitHub 免费构建，**服务器上不需要装 Go 工具链**。

- 仓库：`github.com/Ladavian/SoulFound-ERP`（私有）
- 镜像：`ghcr.io/ladavian/soulfound-erp`（私有包）

### 每次推送代码会发生什么

推送到 `main`（或手动在 Actions 页面触发）时，流水线依次做三件事：

1. **测试**：检查 `gofmt`、跑 `go vet`、跑全部测试
   （含加权平均成本、市集损益、页面渲染、权限隔离，共 20+ 个用例，约 2 秒）。
2. **构建镜像**：同时构建 `linux/amd64` 与 `linux/arm64`，以 manifest list 发布，
   服务器拉取时会**自动选对架构**。打上 `latest`、分支名、`sha-xxxxx` 标签。
3. **构建二进制**：产出 `erp-linux-x86_64` 与 `erp-linux-aarch64` 两个静态文件，
   在 Actions 运行详情页的 Artifacts 里可以直接下载（不用 Docker 时用得上）。

### 发一个版本

```bash
git tag v1.0.0
git push --tags
```

流水线会额外打上 `1.0.0`、`1.0`、`1` 与 `latest` 标签。

### 在服务器上使用预构建镜像

私有包需要一次登录。先到 GitHub 生成一个 **Personal Access Token（classic）**，
只勾选 `read:packages` 即可（Settings → Developer settings → Personal access tokens）：

```bash
echo "<你的PAT>" | docker login ghcr.io -u Ladavian --password-stdin
```

然后在 `.env` 里指定镜像：

```env
ERP_IMAGE=ghcr.io/ladavian/soulfound-erp:latest
ERP_PULL_POLICY=always
```

```bash
docker compose pull
docker compose up -d
```

> 镜像同时支持 amd64 与 arm64，树莓派 / 甲骨文 ARM 实例 / Apple Silicon 都能直接跑。
> 登录信息保存在服务器上，只有拉取时用得到；容器本身不需要任何 GitHub 凭据。

### 两种方式怎么选

| | 服务器本地构建 | 拉取 GitHub 构建的镜像 |
| --- | --- | --- |
| 首次部署耗时 | 需下载 Go 镜像并编译，约 2–5 分钟 | 只下载镜像，约 30 秒 |
| 服务器需要 | Docker + 能拉取 `golang` 镜像 | Docker + 一个只读 PAT |
| 升级方式 | `git pull && docker compose up -d --build` | `docker compose pull && docker compose up -d` |
| 适合 | 想少配一个凭据、想改代码 | 想升级快、服务器弱、多台机器部署 |

两种方式产出的镜像内容一致（同一份 Dockerfile、同一套构建参数）。

## 常见问题

**Q：数字看起来不对，怎么排查？**
先看「库存流水」页，每一笔都有变动后的结存数量、结存均价、结存金额，可以一路倒推。
确认是历史数据被手工改过，就到「系统设置 → 重算全部库存」，按流水重新推演一遍。

**Q：为什么结算时说库存不足？**
因为试饮也消耗库存。比如带 10 瓶、试饮 3 瓶、卖 8 瓶，一共需要 11 瓶，就超了。
补录采购入库，或用「出入库登记 → 盘点调增」把实物库存补上。

**Q：已经结算的市集想改数量怎么办？**
点「撤销结算」→ 修改 → 再点「结算」。撤销会回滚库存并按剩余流水重算平均成本，这是正常的。
如果这场市集已经过去很久、后续又发生了很多采购，撤销会连带影响那些产品的平均成本——
这种情况建议改成「新建一场调整单」，或者直接在库存调整里做一次盘点，而不是撤销历史。

**Q：试饮为什么按瓶记录？**
因为库存是按瓶扣的，按瓶记录才能准确扣减。如果摊位上你是数杯子，
按「一瓶倒 10 杯」换算一下（60 杯 ≈ 6 瓶）再填即可。

**Q：时间 / 日期不对？**
容器时区由 `.env` 里的 `TZ` 决定，默认 `Asia/Shanghai`，改成 `America/Toronto` 就切换成多伦多时间。
改完 `docker compose up -d` 重启生效。已录入的日期不受影响。

**Q：多人同时用会不会冲突？**
不会丢数据。SQLite 开了 WAL，写事务带 10 秒忙等待，并且进程内只使用**一条数据库连接**，
所有读写自然排队——这是小型 SQLite 应用最稳的配置，彻底避免了 `SQLITE_BUSY`。
代价是写入串行：几人同时点保存会排队几十毫秒，对市集现场录入完全无感。
如果你要十几个人高频同时录入（比如几十个摊位同时开单），再考虑换 PostgreSQL。

**Q：为什么店员进不去「出入库登记」？**
盘点、期初建账、损耗调整会直接改账面库存与成本，属于会锁定账目的动作，只给管理员/经理。
市集现场的酒损不需要走这里——直接在市集里填「损耗」数量，结算时会一并扣减并计入成本。

**Q：能换币种吗？**
可以。「系统设置 → 币种 / 币种符号」改的是显示与报表口径。
注意：系统是**单一币种**账套，不做多币种换算；如果你用人民币记账、供应商用加元结算，
建议统一按一个币种记账（汇率差额记到「其他费用」里摊进成本）。

## 本地开发

```bash
# 依赖：Go 1.26+
make run          # 启动（数据写到 ./data）
make dev          # 开发模式：改模板后刷新浏览器即可生效，不用重启
make seed         # 带演示数据启动
make test         # 跑测试（加权平均、到岸成本分摊、市集结算/撤销、报表汇总）
make build        # 编译到 bin/erp
make fmt vet      # 格式化与静态检查
make help         # 查看全部命令
```

模板与静态资源用 `go:embed` 打包进二进制，所以**部署时只需要一个文件**；
开发模式下（`ERP_DEV=1`）会直接读磁盘上的 `internal/assets/`，改完刷新即可。

### 目录结构

```
.
├── cmd/erp/main.go             启动入口 + version / reset-password / backup 命令
├── internal/
│   ├── assets/                 前端模板与静态资源（go:embed 打包）
│   │   ├── templates/          layouts / partials / pages
│   │   └── static/             css / js / icons / sw.js / manifest
│   ├── config/                 环境变量配置、密钥自动生成
│   ├── model/                  领域模型、Money 与 Qty 整数金额类型、加权平均算法
│   ├── store/                  SQLite 访问层（schema.sql + 各实体查询）
│   ├── service/                业务逻辑：库存过账、采购到岸成本、市集损益、报表、导出
│   └── web/                    HTTP 路由、中间件、权限、表单解析、各页面处理
├── deploy/                     Caddy 配置（HTTPS）
├── scripts/backup.sh           定时备份脚本
├── Dockerfile / docker-compose.yml
└── data/                       运行时数据（不提交到版本库）
```

### 技术选择说明

- **Go + `html/template` + HTMX**：服务端渲染，没有前端构建步骤，一个二进制搞定。
  市集现场网络差，服务端渲染的首屏更快、更省流量；HTMX 负责局部刷新，
  录入一行数字只重绘对应面板，不用整页刷新。
- **`modernc.org/sqlite`（纯 Go 驱动）**：因此可以 `CGO_ENABLED=0` 编译出完全静态的二进制，
  镜像基于 alpine 也很小，不依赖 glibc、不需要交叉编译工具链。
- **金额用整数最小单位存储**（1/10000 货币单位、1/1000 瓶）：
  财务数据一律避开浮点，加权平均成本需要 4 位小数精度，因此比「分」多留两位。
- **库存流水台账 + 冗余缓存**：每次变动都写一条不可变的流水（含结存快照），
  产品表上的库存与均价是缓存；「重算全部库存」会按流水重新推演，两者互为校验。
